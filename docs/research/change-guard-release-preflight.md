## 认证、实验与触发

默认 Codex CLI 的官方 `login status` 返回已通过 ChatGPT 登录。默认配置还会加载本机设置，既不能作为 A 组的隔离配置，也无法在外层桌面运行环境中启动此前的 app-server 试验。新实验使用仅设置凭证存储方式的专用目录、单独的临时主目录、禁用插件和记忆的 app-server、每案每组独立工作区及新会话。隔离 `account/read` 没有可用账户。凭证由用户通过官方浏览器登录建立。三个组共用这一实验账户，通过彼此独立的会话使用相同身份及模型。 [Codex 认证](https://developers.openai.com/codex/auth/)

| 实验组 | 实际发现的额外 Skills | 有效模型观测 |
|---|---:|---:|
| A 原生 Codex | 0 | 0 |
| B Codex + 0.11.1 | 34 | 0 |
| C Codex + 候选源码 | 34 | 0 |

app-server 检查了每组额外 Skill 的实际来源路径。六个夹具沿用现有 30 案的代码，并预先设定六类判定：原有编辑、范围偏移、公用 API、授权跨文件修改、小任务开销、过期收据和报告解读。试验脚本以同一模型 ID 和 low 推理配置、同一自然语言提示、同一可调用 CLI 与授权启动三个组。A 组保留原生宿主自带能力。每案轮换组顺序。记录可用的宿主原始 Token、工具次数、耗时、CLI JSON 收据及可观察的调用顺序。客观评分基于文件差异、Git HEAD/暂存状态、定向验证收据和独立行为断言。可观察的命令以实际成功退出为准。未经宿主证实的消耗字段保留空值。 [试验入口](../../scripts/change-guard-pilot.mjs)

两种宿主预检都未调用模型。默认外层沙箱内，app-server 的 `command/exec` 退出 71 并报告权限错误。获批的诊断从外层之外启动，内部仍使用 `workspaceWrite` 并成功返回 `baseline_created`，退出码为 0。这个结果证明本地宿主在获准的执行环境中能运行 CLI。Agent 自主选择、读取三档风险、前后检查、避免重复基线和降级仍缺真实模型证据。输入、输出、缓存及推理 Token，模型工具调用、业务回归、人工干预和真实误报/漏报率均无样本。当前阶段保留六案规模。 [实际预检记录](../../tests/reports/change-guard-0.12.0-pilot-preflight.json)

已登录后可用 `node scripts/change-guard-pilot.mjs --preflight --profile PATH` 检查额外 Skills 和宿主本地命令。真实运行使用同一入口，传入 `--profile PATH --model MODEL_ID --output NEW_REPORT.json` 并省略 `--preflight`。固定宿主实际可用的模型 ID。脚本检查登录与沙箱内 CLI 后才发起模型调用，只使用新报告路径。通过独立终端启动时仍由 app-server 对实验命令执行环境约束。

## 跨平台与测试

macOS arm64 的 Node 18.20.0、20.20.2 与 LTS 24.19.0 的确定性结果继续适用。本轮在 macOS 重新执行了有改动的 CI 契约和 npm tarball 验证。旧 benchmark 的指定案例准备模式也实跑通过。Skill 与生产 Guard 源码保持一致，避免重复运行完整回归。Linux 与 Windows 当前无可用运行环境，本轮未触发远程工作流。

修复了打包测试的两个可复现边界。CRLF 清单现在按完整换行分割。Windows 的默认目录夹具显式使用 Node 在 Windows 上读取的 `USERPROFILE`，避免测试命中真实用户目录。CI 矩阵在三平台覆盖 Node 18 及 LTS。更新后，所有最小版本和非 Linux LTS 组合执行完整 tarball 检查，Linux LTS 由独立质量作业覆盖。这一修改尚待 Windows 和 Linux 实跑。 [CI 定义](../../.github/workflows/ci.yml)

对冻结并获准运行的候选，保留同一提交的完整 Actions 日志，核对每个 OS/Node 组合的 Git 编码和 CRLF、原有修改与 Git Worktree、并发、已暂存和未暂存、路径保护、tarball 安装替换及清理结果。Linux 用大小写敏感工作区。Windows 运行可用的 Git 路径和链接保护用例，并记录现有 Windows 权限跳过。Unix 执行位和真实符号链接由 Linux/macOS 用例提供证据。如需覆盖 Windows 符号链接本身，使用已允许创建符号链接的隔离 runner，保持检查和跳过原因可见。发布前核对候选升级与卸载的实际宿主数据。

## 分阶段发布判定

| 阶段 | 判定 | 依据与进入条件 |
|---|---|---|
| 本地开发与 macOS 定向试用 | GO | 开发门禁、实际包和真实 Git 示例支持明确限定范围的本地试用。 |
| Beta 公开预发布 | BLOCKED | 当前版本及标签门禁是历史正式合约，开发模式只检测一致性。先冻结独立 Beta 版本及绑定证据，明确目标平台及已验证的手动或 Agent 流程，运行该范围的安全、打包和安装回归。CLI 定向 Beta 可以明确限制为手动流程，完整 30 案及超大仓库压力测试可后置。不得把开发一致性检查用为发布批准。 |
| RC | BLOCKED | 需要跨平台实际日志、认证后的关键六案、候选安装升级证据，以及候选源码对应的 RC 发布检查。 |
| Stable | NO-GO | 上轮实际正式门禁拒绝历史源码/运行时与 npm 清单证据。相关绑定本轮仍未改变。稳定版需保留正式门禁标准，补全与冻结候选相匹配的模型、平台和分发证据。 |

本轮没有切换项目版本、历史证据或正式门禁。下一步的唯一即时用户操作是在专用目录完成官方浏览器登录。认证通过后可运行六案。跨平台公共发布另需可用 runner 或候选上的获授权 CI 触发。 [双语发布草案](../RELEASE_NOTES_0.12.0_DRAFT.zh-CN.md)
