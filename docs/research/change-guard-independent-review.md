# Change Guard 独立审查与 0.12.0 发布预检

2026-11-24，审查对象为 `112ab7d` 上的本地升级差异。结论为 **NO-GO，保留 0.12.0 草案**。本地证据表明 Change Guard 能持续发现 Git 可见的范围偏移和已有改动被触及。模型级收益仍待测量。历史发布元数据的正式门禁也已实际运行并拒绝当前源码。

## 审查结果

| 审查轴 | 结果 |
|---|---|
| 仓库符合度 | 保留 JS ESM、现有工作流、公开 CLI 和安装入口。新增代码复用项目绑定、路径校验、凭据检测、私有文件、锁和原子写入。独立审查修复仅涉及 Guard、直接回归和验证材料。 |
| 变更意图 | 确认下列三项报告缺陷并补上回归。现有实施和修复 Skill 会加载工作区安全规则，其中的 Guard 调用是可选路径。运行时缺失时可继续人工基线及最终差异检查。 |
| 运行安全 | 真实本地 Git 验证覆盖暂存、未暂存、未跟踪、删除、重命名、执行位、类型、链接工作树、子模块、Unicode 路径和 CRLF 文件。检测到的内容变化来源保持未知。索引字节在捕获和检查前后一致。损坏基线结构化报错，损坏文件保留原状，并发同 ID 基线只有一位创建者。 |

| 确认缺陷 | 修复与证据 |
|---|---|
| P1，保护路径的大小写别名可漏报 | 在大小写不敏感的本机文件系统上，`SRC/KEEP.JS` 与实际 Git 路径 `src/keep.js` 指向同一文件。原报告漏掉保护规则，还误报 `SRC` 范围偏移。比较时使用文件系统确认的路径拼写，基线保留现有别名，文件和符号链接删除后仍可命中保护规则。符号链接通过同一文件身份确认名称，过程中只读取链接元数据。大小写敏感文件系统继续区分实际不同的路径。 |
| P2，已存在的执行位和类型可被重复报告 | 已有执行位变化以后修改同一文件的正文，旧程序仍拿当前 Git 状态与 HEAD 比较。现在对比基线和当前的暂存/工作区模式，测试同时检查真正恢复模式或文件类型仍被报告。 |
| P2，单条不可达范围遮蔽有效报告 | 声明路径位于符号链接内部时，原批量 Git 忽略检查使整次观测返回未知。现在将该路径单独标为 `declared_scope_unreachable`，其他路径及其违规保持可见。 |

回归和实现见 [Change Guard 测试](../../scripts/test-change-guard.mjs) 与 [Change Guard 实现](../../scripts/change-guard.mjs)。

**潜在风险和设计取舍。** 两次采样之间仍存在竞态，工作区和 Git 配置需要宿主信任及适当的隔离。基线校验和用于发现损坏，本地状态依赖宿主文件权限。识别为敏感的路径只报告可观察元数据，内容变化可为未知。报告也含相对路径和分支名，分享时需考虑这些名称的敏感性。禁用已配置的 Git 过滤器和 fsmonitor 保护本地读取，代价是有外部过滤器的环境可能出现保守的未知提示。

**已知漏检边界。** Git 忽略文件、`assume-unchanged`、`skip-worktree`、子模块内部修改和观测间被覆盖的改动都可能不可见。夹具实测了隐藏索引项及子模块内部修改，后者的 gitlink 变化可以单独观察。HEAD 或分支变化让报告覆盖标为未知。Git 只提供可观察的文件类型与执行位，未暂存的重命名可能表现为独立删除和新增。作用域命中依据 Git 路径及可确认的文件系统别名，无法安全解析的路径仍需人工复核。

## 真实模型评估状态

A 原生 Codex、B 0.11.1、C 当前版本的正式任务均为 **0 次可用观测**。现有认证试跑的 app-server 在默认配置目录启动被宿主拒绝。隔离目录中初始化成功，`account/read` 返回无账户并要求 OpenAI 认证。D/E 的 Superpowers 对照未启动。模型名称、模型任务正确率、业务回归、权限或范围误报/漏报率、验证完成率、虚假完成、人工干预、工具调用和模型耗时，均无可报告的样本。输入、输出、缓存和推理 Token 同样未采集。上表只测量本地命令和文件。

现有准备模式复核了 24 个夹具文件、两组各 34 个 Skill 及 30 个案例。旧准备流程没有为案例创建 Git 基线或安装 Guard CLI，适合复核现有任务台。Guard 对照需要给每组准备相同的 Git 初始索引、已有修改和工具。真实对照延用同一夹具、提示、权限、工具、模型版本、推理配置和新会话。先试运行现有 `simple-en-doc-typo`、`simple-en-button-text`，再用原夹具的跨模块改动及预先写入的用户修改检验保护效果。对关键用例预先固定每组重复次数，随机组顺序并保留失败、超时和阻塞结果。三组都使用相同的 CLI 工具可用性，避免把额外工具权限误算为 Skill 收益。现有 30 个案例中，有显式 Skill 输入的案例继续作为激活回归，A/B/C 工程评分使用统一的自然语言任务与独立行为断言。旧评估器的 `selected_skill` 和工作流偏好不计入跨组正确率。测试收据区分模型实际运行和裁判事后运行，宿主原始 Token 字段与估计值分开。 [现有基准运行器](../../scripts/live-performance-benchmark.mjs)

## 发布判断

当前可作为核心卖点的能力是可复查的 Git 可见范围漂移、已有改动保护提示、分级的未知覆盖，以及 Skill 的可选降级。从 v0.11.1 标签导出并运行同一命令时，旧版本返回未知命令和退出码 2。当前源码返回结构化的缺少基线状态，打包版也通过完整 Guard 流程。相对原生 Codex 和其他 Skills 的用户收益、简单任务负担及互补效果尚无真实对照证据。

macOS 上 Node 24.19.0 完整回归通过，其中状态与 CLI 61 项，Change Guard 14 项。Node 18.20.0 和 20.20.2 各通过 19 项定向测试，Node 18 另通过实际 tarball 安装回归。Linux 和 Windows 待实跑。正式 `release:check` 拒绝当前历史证据，原因是源码/运行时内容绑定已变更，且 0.11.1 补丁提升记录对应旧 CLI 与 npm 清单。开发一致性检查维持原标准。本地保留未发布版本的候选说明和 Unreleased 记录。正式发布条件包括认证隔离的 A/B/C 试验与关键场景复测、Linux/Windows 检查、切换项目和受影响插件版本元数据、验证候选安装与升级，以及使用候选源码生成并核验匹配的发布证据。 [0.12.0 草案](../RELEASE_NOTES_0.12.0_DRAFT.zh-CN.md)
