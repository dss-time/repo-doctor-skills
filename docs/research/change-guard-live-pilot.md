# Change Guard 真实模型六案试验

2026-11-24，macOS arm64。主样本由原生 Codex、Codex + Repo Doctor 0.11.1 和 Codex + 当前候选各执行同样的六案。以宿主上报的 `gpt-6.2-sol` 和 `low` 推理配置为准。0.11.1 基线为 `112ab7d`，候选的 Skill 源与分发树、CLI 和夹具绑定见原始报告。 [主试验原始报告](../../tests/reports/change-guard-0.12.0-pilot-live-2026-11-24.json)

## 组间隔离与判分

- 三组共用同一隔离账户、运行时和工具 PATH。A 组发现 0 个额外 Skills，B 和 C 分别发现 34 个，来源路径均限定在对应工作区。各组每案从同一 Git 夹具复制，运行前比较代码哈希，使用新建的临时会话。实验目录独立于用户日常配置，宿主插件、应用与记忆关闭。任务的模型、推理、提示、授权与沙箱策略一致。按案例轮换 A/B/C 顺序。
- 六案分别覆盖已有修改、范围偏移、公共 API、授权跨文件修改、简单文案和只读的过期收据与风险报告。客观评分核对改动路径、用户标记、Git HEAD 与暂存状态，按任务核对行为断言及成功退出的宿主验证记录。只读案例预先用真实 CLI 生成报告，模型再解释报告和历史收据。
- 最初的判题有两处错误。已有修改案把原 benchmark 的大写归一化写成小写。其他三个修改案使用了未规范化的 macOS 临时目录，为 Node 读取权限提供了路径别名，导致真实文件读取被拒绝。原报告保留这 12 条原始评分。对对应三组产物离线复核时，按原 benchmark 契约检查大写，并用规范路径执行原有断言。权限范围、预期改动、实际运行和行为判据继续一致。两项离线复核均未消耗新的模型调用。 [归一化复核](../../tests/reports/change-guard-0.12.0-pilot-existing-edits-rejudge.json) · [路径复核](../../tests/reports/change-guard-0.12.0-pilot-permissions-rejudge.json)

首个进程在写入 16 条有效观测后退出，日志只保存了通用失败提示。续跑单独记录缺失的 A/B，只读案仍用原 180 秒超时。隔离 Codex 自动记录了 15 个写任务的旧项目路径及信任标记。续跑仅接受这类标记，并确认路径均已清理，新工作区与旧标记无匹配。续跑重新核对候选源码绑定和只读夹具哈希。 [续跑记录](../../tests/reports/change-guard-0.12.0-pilot-continuation-2026-11-24.json)

## 结果

18 条有效主样本均由同一宿主模型 ID 完成，未收到模型改路由事件。主样本中断产生的额外未完成执行不计入这 18 条。

| 组别 | 有效任务通过 | 自动 Guard 调用 | 完成的工具项 | 单案耗时中位数 |
|---|---:|---:|---:|---:|
| A 原生 Codex | 6/6 | 0 | 20 | 129.2 s |
| B Codex + 0.11.1 | 6/6 | 0 | 28 | 138.8 s |
| C Codex + 当前候选 | 6/6 | 0 | 32 | 140.0 s |

- 已有修改案三组生成了相同结果并保留原注释。范围偏移案三组都保留了原有范围外锁文件编辑，完成授权配置修改并实际运行定向检查。六案中各组均无观测到的额外项目文件变更、HEAD 或暂存状态偏移。四个修改案的 12 条独立行为断言在复核后通过，另外复跑的三组按钮定向测试同样通过。覆盖范围仅限夹具的断言。
- 三组简单文案和只读案均未调用 Guard 或运行全量检查。三组还在只读案中识别出过期收据，并正确关联 `warning`、`violation` 和 `unknown` 到各自路径。该报告由夹具预先生成，结果证明这些回答能解读已提供的报告。
- 主样本中候选组四个修改案均无 Guard 命令收据，公共 API 案也未观察到开始与结束的基线比较。因而没有可用于评估自动 Guard 误报率或漏报率的动态报告。范围内编辑与原有范围外修改在夹具中均得到保留，不能据此估计检测漏报或业务回归的总体发生率。

## Token 和计时口径

首轮进程保存宿主的 `tokenUsage.last`，下表按每组 6 条记录求和。输入列包含宿主单列的缓存输入，不能再相加。`last` 为宿主上报的最后一笔用量，整个线程的累计用量另见 `total`。两种口径不可混用。耗时是从提交任务到宿主完成整个轮次的墙钟，中断时间单独保留。工具项是宿主记录的完成事件。

| 组别 | 最后一笔输入 Token 合计 | 其中缓存输入 | 最后一笔输出 Token 合计 | 其中推理输出 |
|---|---:|---:|---:|---:|
| A | 95,545 | 92,672 | 698 | 0 |
| B | 142,946 | 139,520 | 660 | 0 |
| C | 150,674 | 144,640 | 658 | 0 |

A/B 只读案续跑还记录了整线程累计读数。A 为输入 61,785、缓存输入 43,264、输出 504，B 为输入 105,647、缓存输入 82,560、输出 580，推理输出均为 0。原始其余 16 条缺少累计字段，无法报告主样本全组累计开销。六案中三组通过数相同，候选的完成工具项和墙钟中位数均较高。小样本与顺序运行中的服务波动限制了对成本差异的解释。

## 候选组关键复测

用两个新的候选组会话复测公共 API 和只读报告，保持模型、推理配置、提示、任务授权以及初始夹具哈希。两个复测均通过，均无 Guard 调用。只读复测保存了模型原答复。它将敏感文件的超范围违规和指纹未知分开，建议确认范围且保护文件内容。它还识别了锁文件范围偏移和既有修改警告，建议保留现有工作，并在新验证获准后核对当前 API 契约。 [候选组复测与原答复](../../tests/reports/change-guard-0.12.0-pilot-retest-2026-11-24.json)

| 候选组复测 | 耗时 | 工具项 | 整线程输入 | 其中缓存输入 | 整线程输出 | 其中推理输出 |
|---|---:|---:|---:|---:|---:|---:|
| 公共 API | 57.7 s | 5 | 142,310 | 115,328 | 552 | 0 |
| 只读报告 | 27.9 s | 3 | 82,138 | 39,296 | 478 | 23 |

复测耗时明显低于对应主样本，进一步说明本轮不足以稳定比较延迟。复测独立列出，主对照仍以每组六个有效样本为准。

## 发布判定

| 阶段 | 判定 | 依据 |
|---|---|---|
| macOS 本地显式 CLI 试用 | GO | 真实 Git 夹具、隔离宿主命令和本地 tarball 已经验证。可对外展示工作区前后比较、已有修改提示、范围偏移与未知覆盖。 |
| 公开 Beta | BLOCKED | 先冻结候选版本、分发产物和适用平台，并收集匹配的安全与升级记录。Beta 的宣传范围可以限定为显式 CLI。当前对照支持报告可读性，自动调用暂缺有效观测。 |
| RC | BLOCKED | 仍缺 Linux/Windows 实跑、冻结版本的升级验证，以及与候选发布标识一致的门禁证据。若列出 Agent 自动 Guard 能力，需要可复现的真实自动调用与前后报告。 |
| Stable | NO-GO | 当前正式门禁仍验证历史合约，已拒绝不匹配的历史证据。六案是候选证据的一部分。稳定版仍需符合正式发布要求，并核验目标平台与分发。 |
