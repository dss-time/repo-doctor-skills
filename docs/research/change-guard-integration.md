# Change Guard 共享集成专项验证

## 自动调用为何遗漏

历史六案的候选组及两次关键复测均无自动调用。历史轨迹没有保存足以确认 Skill 正文已读取或 Router 已执行的证据，因此各轮的具体原因仍为 unknown。代码和产物确认了两个问题。调用规则位于末尾引用后的可选段落，单装 Skill 或插件时也没有可执行入口。历史隔离环境预先配置 CLI 后可以运行它。发现 Skill 与执行 Skill 分别计量。 [历史试验](change-guard-live-pilot.md)

现在功能实现、安全修复、安全测试和文档同步可以直接使用随 Skill 分发的同一运行时，CLI 使用同一实现。Skill 前部给出已有修改重叠、公共契约等写入前的判断与调用方式，共享规则覆盖范围、权限、并发和交付。只读及可控的低风险任务使用轻量检查。Task ID、工作树、范围与基线一致时可跨阶段复用，有新的写入时刷新检查。错过首次写入保留未知，避免补建基线冒充事前覆盖。告警和规则违反交给助手核对实际差异和授权，用户代码由原工作流保留。两个独立安装的 Skill 入口复用同一基线和保护策略已有确定性测试；真实多阶段任务只确认读过一个 Skill。

## 可选宿主 Hooks

已安装 Codex 的 `hooks/list` 在空白临时配置中实测返回空列表且无警告或错误，未执行任何 Hook。该版本的协议 schema 包含 `hooks/list`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop` 和子代理启停事件。官方文档列出 Bash、unified exec 和 apply_patch 等工具匹配边界。Shell 写入意图无法普遍识别，收到提示也无法推导授权。Claude Code 当前官方文档提供生命周期事件，但本机 1.0.70 的事件覆盖和行为未实测。D 组没有安装、信任或运行适配器。 [Codex Hooks](https://developers.openai.com/codex/hooks/) · [Claude Code Hooks](https://code.claude.com/docs/en/hooks)

可选适配器只以用户信任的配置及现有已授权任务、工作树、范围交接为前提。识别出相关写入时，由 PreToolUse 在安全时机补足尚未建立的基线。PostToolUse 只记录变化，Stop 在有新写入时检查一次，子代理复用协调者的任务身份。排除 Guard 自己的调用以防递归。无法匹配的写入、拒绝执行或竞争条件保留 unknown，继续人工流程。先验证其他 Hook 共存和未覆盖路径，再扩大适用范围。

## 候选冻结和本轮补验

候选功能和公开接口维持冻结，生产代码、Skill、CLI 和评分规则均未修改。以构建输入、Skill 源码及分发树的指纹标识本地内容冻结。npm 元数据继续标记已发布的 0.11.1，这份冻结记录供本地验证。 [候选指纹与结果](../../tests/reports/change-guard-0.12.0-freeze-2026-11-24.json)

公共模块案例与受保护路径案例修改同一个公开导出的返回字段。公共模块旧轨迹两次都出现 `safe-fix-implementation/SKILL.md` 路径，复测没有成功正文读取凭据。受保护路径任务同时具有本地路径策略与明确的报告要求，留下正文读取与 Guard 收据。候选 Skill 明确要求在公共契约变更前建立基线，已安装入口可在公共模块夹具上成功运行。已有轨迹可以定位到调用遗漏，无法区分正文未读、读取方式未被捕获或 Agent 跳过指令。授权提示和策略条件也有差异，不能单独归因为其中一项。暂未发现需要修改产品源码的缺陷。

追加的公共模块、受保护路径和已有修改三案保持相同模型、low 推理、夹具、提示、授权和判定条件。账户及内置运行时探针通过，三轮在首次工具调用前均返回 `usageLimitExceeded`。没有新增有效 Token 或行为观测。旧样本的只读报告解读仍有效，已有修改与受保护路径的写入轨迹只证明去向和检测。Agent 是否正确处理修改任务里的 `warning`、`violation`、`unknown`，仍需待同模型额度可用后核验。 [本轮原始重试记录](../../tests/reports/change-guard-0.12.0-freeze-retest-2026-11-24.json)

在 macOS arm64 上，将官方 Node 18.20.8 压缩包按官网 SHA-256 校验后解包到临时目录。候选构建、Guard 15/15 以及完整 npm tarball 测试通过。Node 18 与 24 的两个独立构建目录中，社区 Skills、插件、各平台产物、ChatGPT ZIP 与 npm 运行资源逐文件一致。候选质量检查通过，双语 34/34、构建目标 7/7、ZIP 34/34。

升级起点使用与 npm 公共登记的 SHA-512 相符的已发布 0.11.1 tarball。Node 18 和 24 均成功将同一隔离目录的 34 项升级，现有自定义 Skill 保留，随后重复安装识别 34 项未变。旧项目状态可读，旧任务仍要求宿主复核凭据。升级后的 Skill 入口和 CLI 可以共享同一基线。人工注入的范围外文件被报告，索引未改，公开字段断言通过。以上为确定性升级与运行时证据。

本机缺少 Linux 或 Windows 运行器。获准使用远程 CI 后，将完全匹配冻结输入的工作树放到隔离候选分支，让现有三平台 Node 18/LTS 矩阵运行。另一途径是在已有 Linux 与 Windows 机器上对同一快照执行 `npm ci`、`npm run validate`、`node --test scripts/test-change-guard.mjs`、`node scripts/test-installer.mjs` 和 `npm run test:npm`，保留平台版本、源码摘要和退出结果。当前没有提交候选分支或触发 CI。
