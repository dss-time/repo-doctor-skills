# v0.7.0 usability and prompt design brief

## Scope

Update existing public Skills in engineering.repo-doctor; keep stable slugs and specialist ownership. Improve the shared installer and bilingual user documentation. Generated plugins and skills.sh files remain projections of canonical packs.

## Requests and boundaries

- Review a small diff: findings and evidence, without edits or empty report sections.
- Diagnose an intermittent failure: qualify the signal and causal evidence; do not implement a repair under diagnosis-only authority.
- Fix and verify an explicitly scoped defect: continue the authorized work without asking for the same authorization again.
- Add a regression test: preserve behavior-based assertions and honest sensitivity evidence.
- Recommend a Skill: Router remains recommendation-only and never assumes missing capabilities.

Production access, destructive operations, releases, and new material decisions never gain authorization from concise output or a lower execution mode. Test-only and read-only Skills retain their boundaries; an authorized end-to-end workflow may continue under the appropriate owner.

## Resources and output

Keep necessary safety and evidence rules in the installed Skill. Consolidate duplicated mode and output declarations; use the existing execution reference for detailed mode selection. Default answers report the result and decisive evidence, with limitations only when material. Detailed command ledgers belong to audit output.

Keep bilingual distribution as default. Optional installer --language selects one complete body and retains all resources, so references never disappear. Do not assume byte savings equal token, latency, or quality gains.

## Verification

Verify installer idempotence, Recommended-to-Full expansion, individual selection, language bodies, modified-file conflicts, unknown flags, symlinks and isolated targets. Preserve 40 active Skills, 7 Recommended, 37 ZIPs, YAML validity, distribution parity and repeat-build hashes. Recheck activation and permission contracts; historical live-model reports are historical evidence, not a new measurement of changed prompts.

## Exclusions

No new Skill, alias, automatic Router executor, changed security permission, or arbitrary deletion of specialized references.
