# 执行模式

Repo Doctor 根据任务风险分配执行成本。Skill 专业并不意味着必须自动执行完整审计。

## 选择模式

| 模式 | 适用场景 | 范围与验证 | 默认输出 |
|---|---|---|---|
| `fast` | 请求明确、局部、低风险、可回滚，且不涉及生产数据、安全、迁移、发布、公共契约破坏、依赖升级或大型架构变更。 | 一个主 Skill；优先用户指定文件；3 个文件和 3 个命令的软预算；一个定向检查；不运行全量测试/构建，不创建持久化审计报告。 | 结论、完成或发现的内容、最小验证，以及至多一个下一步建议。 |
| `standard` | 涉及多个相关文件、普通功能或 Bug、模块级验证，或少量非重大未知项。 | 只读相关模块；运行受影响测试以及必要类型检查/lint；保留足以支持结论的证据；不默认执行全仓库发布门禁。 | 结论、影响范围、相关证据、验证、剩余风险和一个可选下一步。 |
| `audit` | 涉及安全或权限、生产数据、数据库迁移、发布、公共契约破坏、依赖升级、大型架构变更，或用户明确要求完整审计。 | 完整证据、命令和权限账本；完整风险与停止条件；只有获得授权且确有必要时才执行全量测试/构建。 | 完整证据、风险、权限、命令、未知项和停止条件记录。 |

符合条件时默认使用 `fast`。文件和命令数量是软预算；若正确完成需要更多，Skill 会先说明原因并升级为 `standard`。

## 简单请求快速通道

解释字段、定位明确报错、修改显示文本或 CSS、修复局部类型错误、修改已确定配置或解释代码，不需要完整执行“澄清 → 规格 → 计划 → 实现 → 测试 → 审查”链。主 Skill 读取直接相关内容，回答或完成最小授权修改，执行最接近的定向检查，简洁报告并停止。

每个请求默认只激活一个主 Skill。Skill 可以推荐下一 Skill，但除非用户明确要求端到端流程或自动继续，否则不能执行它。Router 是显式推荐工具，不是必经中间层。

## 指定模式

使用平台真实支持的显式 Skill 语法，并用自然语言说明模式：

```text
使用 $bug-root-cause-analysis 以 fast 模式诊断这条明确的本地报错。
使用 $architecture-deepening-analysis 以 audit 模式分析这个跨模块重构。
```

本仓库不声称支持 `mode=fast` 参数，也不编造跨平台 alias。

## 仅显式调用的 Skills

Codex 可安装 Skill、插件 Skill 和 ChatGPT 包会为重型或容易误触发的专项 Skill 生成 `policy.allow_implicit_invocation: false`，包括发布、迁移、依赖升级、安全、性能、架构深化、配置审计、会话交接、全仓库体检、ADR、原型和 Router 入口。请通过 `$<skill-name>` 调用。

其他构建目标没有经过仓库核验的等价策略字段，因此使用精确的“仅显式调用”description 和 canonical execution 元数据，不创建虚假 alias 或包装 Skill。

## 安全性不变

执行模式不改变文件系统、Shell、网络或危险操作权限。`fast` 不能绕过写入授权、命令预检、生产数据边界、证据真实性或危险操作停止条件。不安全或未授权的工作必须停止。

详细 canonical 规则位于：

- `packs/engineering/repo-doctor/references/execution-modes.zh-CN.md`
- 每个 Skill 的 canonical `skill.yaml` `execution` 块
- `tests/performance-contracts/cases.json`
