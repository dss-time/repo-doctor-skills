# 自然语言使用案例

[English](repo-doctor-scenarios.md) · [快速开始](../../README.zh-CN.md)

这些提示可以直接改成你自己的需求。订单示例展示如何在日常项目里应用工作流，链接中的夹具记录了实际运行结果。

| 你可以这样说 | 交付时可以核对什么 |
| --- | --- |
| “修复订单编辑后列表没刷新，现有业务规则保持原样。” | 追踪更新和刷新链路，限制改动范围，用定向回归验证修复行为。 |
| “给订单页加个搜索条件，保留我的未提交修改。” | 适合建立基线时，比较任务中的 Git 变化，核对原先已编辑的路径有没有再次被触及。 |
| “修改这个组件的样式，其他模块不要动。” | 明确允许修改的文件，将最终变更路径与范围对照。发现偏移时先核对差异和授权。 |
| “修复 TypeScript 类型错误，依赖保持原样。” | 检查基线之后的依赖清单和锁文件变化，再由开发者决定是否接受。 |
| “优化公共请求方法，确保其他接口正常运行。” | 核对调用方、公共契约和受保护路径。Codex 公共模块夹具曾漏触发自动调用，随后复测完成了基线和检查。 |
| “帮我修改这个按钮的文案。” | 对目标文本做定向检查。Codex 低风险夹具保持轻量，未建立基线。 |
| “实现订单批量审核，并补充测试。” | 按范围分阶段交付。涉及权限时验证允许和拒绝两类结果。现有 Skills 可以共享仍有效的基线和工程证据。 |
| “续接上次任务，确认问题是否已经修好。” | 检查工作树、相关输入和宿主凭据。复用仍有效的证据，只重做受变化影响的验证。 |

工作区检查报告 Git 可见的事实。Agent 负责理解任务并说明实际执行的测试。覆盖未知时，核对已授权的差异并验证关键业务行为。 [可复现 Git 夹具](change-guard-demo.zh-CN.md) · [实测结果和限制](../research/change-guard-integration.md)
