# 完整交付样例

[English](delivery-examples.md) · [工作流手册](../WORKFLOW_COOKBOOK.zh-CN.md)

以下均为虚构演示，不是本仓库实际执行的命令或测试结果。路径、脚本名和结果用于说明应收集哪些证据；真实命令必须从目标项目清单解析。`feature-implementation` 包含在 v0.8.0 中，v0.7.3 不包含它。

## 1. 交付已确认的 CSV 导出功能

**已确认契约：** 导出当前筛选结果并保持显示顺序；列为 `name,email`；空值输出空单元格；逗号、双引号、换行按 CSV 规则转义；失败时提示错误并保留当前页面。不修改认证或公共 API。已授权源码、相关测试和导出帮助文档；不安装依赖或发布。

启动请求：

```text
$feature-implementation 实施下方已确认的 CSV 导出契约。
范围：src/export/、tests/export/、docs/export.md。
允许预检后执行本地验证；不安装依赖、不改认证、不提交或发布。
契约：<上面的已确认契约>
```

已有规格充分、影响已知时直接复用，不制造额外澄清或规划阶段；缺少重大行为决策时先解决，再改代码。

| 切片 | 实施与证据 | 完成条件 |
|---|---|---|
| 单元格序列化 | 在公共序列化边界，以 `test_first` 真实证明缺少转义导致测试失败，再最小实现并运行同一检查。 | 普通值、空值、逗号、双引号及换行均符合契约。 |
| 导出筛选结果 | 复用已有筛选状态，不改变筛选逻辑和顺序，运行相关集成检查。 | 导出行与当前筛选结果顺序相同，列符合约定。 |
| 失败处理和说明 | 失败时保留页面并提示约定错误，更新授权范围内的帮助页。 | 错误行为有验证证据，文档与实际实现一致。 |

运行前检查包脚本及钩子。假设示例项目定义了 `test:export`，应记录准确命令、退出码和断言结果；仅看到 manifest 中存在命令不能算通过。下一依赖切片开始前先修复当前失败，未变化且已完成的切片保留原有效证据。

最终报告示意：

```text
已完成授权范围内交付：CSV 序列化、筛选顺序和失败处理已实施，帮助页已同步。
修改路径：<实际路径>。
验收证据：<验收项 -> 测试/位置 -> 实际结果>。
验证：<实际定向命令、退出码和简洁结果>。
审查：<实际发现及处理结果>。
尚未发布或部署。
```

有验收项缺少证据时，状态应为“部分完成”。上述报告不授予发布权限，发布门禁属于独立决策。

## 2. 修复已诊断的局部 Bug

**示例观察：** 公共解析器在可选字段为空时触发空值错误。诊断已给出失败输入和具体分支；预期为空值，不影响非空非法输入的拒绝行为。

1. `bug-root-cause-analysis` 记录复现、预期/实际结果及有证据的根因；原因不明时不直接猜测修复。
2. 已授权生产代码和测试写入后，`safe-fix-implementation` 只修受影响的空值分支。编写测试时遵循 `safe-test-implementation` 对应模式：`test_first` 必须真实红灯；修复后补测试使用 `regression_after_fix`，报告敏感性证据，不编造历史红灯。
3. 运行定向回归和相邻非法输入检查；最终报告引用修改路径、真实结果与剩余不确定性，不顺手扩大清理范围。

测试运行器缺失时，合格结果是：

```text
部分完成：范围内解析修复已实施，但 <所需运行器> 不可用，验证尚未完成。
待运行检查：<manifest 定义的命令>。未安装依赖。
运行器可用后，先核对当前 diff，再执行该命令，通过前不声称验证成功。
```

## 3. 交接必须由人完成的阻塞步骤

只有当前工具和授权无法完成必要步骤时才使用，不把普通可执行工作转交给用户。

示例：此前已授权的操作返回官方浏览器认证链接，需要账户所有者确认。

| 字段 | 给用户的信息 |
|---|---|
| 操作位置 | 工具实际返回的官方认证链接，以及正在等待的本地终端；不编造链接或后台路径。 |
| 具体动作 | 用户自己打开链接，核对目标账户并批准所需认证，秘密值仅输入可信官方界面。 |
| 成功标志 | 本地 CLI 提示认证完成，或账户所有者明确告知完成；仅打开网页不算成功。 |
| 恢复步骤 | 告诉 Agent“认证完成”；Agent 核对不敏感的账户/状态信号，再恢复此前已授权的操作。 |

不要求在聊天里粘贴密码、token 或验证码，不因时间经过就推断完成，也不自动重试发布。等待时可以继续独立且已授权的工作；相关依赖步骤必须等到成功信号出现。目标账户、操作目的或授权范围改变时，先解决新的决策。
