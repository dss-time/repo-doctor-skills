# 示例

用户：“需求和影响分析已经确认，请给出原子化、可回滚的实施计划，不要改文件。”

预期：检查输入充分性，锁定范围，按依赖排列单一目的步骤，并为每步附验证和回滚。

反例：“认证可能要改一下，先做个计划。”应先使用 `requirements-clarification`。

# 补充示例

- “把已批准的账户恢复规格拆成可独立测试的工作项，包含兼容、审计日志、文档和回滚。”
- 合格切片应交付“符合条件的用户完成恢复”“未授权恢复被拒绝且可观察”等行为，并各自包含测试。
- “数据库任务 / 后端任务 / 前端任务 / 测试任务”若不能独立交付或验证行为，应拒绝。
- 反例：“为这个计划创建 GitHub Issues。”外部创建需要单独明确授权并确认平台支持。
