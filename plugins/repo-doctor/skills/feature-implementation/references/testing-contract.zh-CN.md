# 行为测试契约

- 选择并声明一种模式。尚未实现的行为使用 `test_first`：生产实施前运行最小测试，观察因预期行为缺失导致的真实失败。无关失败、flaky 和命令不可用都不是红灯证据。
- 修复已存在时使用 `regression_after_fix`，不要求历史红灯；通过安全的修复前对照、隔离副本中的可逆变异或精确断言—缺陷映射证明敏感性，否则标为 `sensitivity_unverified`。
- 固定已有行为使用 `characterization`。首次运行可以通过，说明断言能够区分哪些有意义的可观察状态。
- 断言调用者可见的输出、错误、状态转换或副作用，不绑定私有方法或内部调用顺序，不为测试暴露私有 API。Mock 需有系统边界理由，可行时优先真实本地替代。
- 使用现有工具，每次完成一个行为切片。检查命令及钩子，执行定向检查并记录真实证据，绿灯后才整理。不得编造红灯、绿灯或敏感性；工具缺失或不安全命令只阻塞受影响检查，不阻塞独立且已授权工作。
- 本资源不授予权限。调用 Skill 保持自身授权编辑范围；仅测试任务不授权生产修改、依赖安装或发布。
