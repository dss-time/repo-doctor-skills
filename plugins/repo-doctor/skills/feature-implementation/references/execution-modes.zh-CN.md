# Repo Doctor 执行模式

根据风险、范围、可回滚性和授权选择执行模式，不得因为 Skill 本身专业就提高执行成本。

## `fast`

用于问题明确、范围局部、风险低、容易回滚，且不涉及生产数据、安全或权限、迁移、发布、公共契约破坏、依赖升级或大型架构变更的请求。

默认预算：

- 只激活一个主 Skill；
- 优先读取用户指定文件，不扫描全仓库；
- 最多读取 3 个直接相关文件并执行 3 个必要命令；
- 只做一个定向语法检查、测试、类型检查、lint 或最小复现；
- 不运行全量测试、完整构建或发布门禁，不创建持久化审计报告，不自动串联 Skill；
- 输出仅包含结论、完成或发现的内容、最小验证，以及至多一个下一步建议。

文件和命令数量是软预算。若正确完成必须超过，应先说明原因并升级为 `standard`。

## `standard`

用于多个相关文件、普通功能或 Bug、模块级验证，或少量非重大未决细节。只读取相关模块，运行受影响测试以及必要的类型检查或 lint；保留足以支持结论的证据，但不默认执行全仓库发布门禁，也不自动进入 audit。

## `audit`

仅用于数据库迁移、安全或权限边界、生产数据、发布决策、公共契约破坏、大型架构变更、依赖升级，或用户明确要求完整审计。保留证据状态、命令和权限账本、完整风险与停止条件；只有在获得授权且确有必要时才运行全量测试和构建。

`fast` 不得放宽权限、危险操作禁令、证据真实性、数据处理或审批门禁。请求不安全或未授权时必须停止，而不是降低成本后继续。

## 简单请求快速通道

当请求已经明确、局部、低风险，且不需要产品决策或跨模块设计时：

1. 读取直接相关内容；
2. 回答或只做最小授权修改；
3. 执行最接近的定向检查；
4. 返回简洁结果；
5. 停止。

不得把字段解释、明确报错、文本或样式调整、局部类型修复、已确定配置修改或代码含义问题扩展为澄清、规格、计划、实现、测试和审查流水线。

## 单一主 Skill

每个用户请求默认只激活一个主 Skill。Skill 可以推荐一个下一步 Skill，但不得执行或路由到它；只有用户明确要求端到端流程、连续完成分析/实现/验证或自动继续时才可串联。Router 只负责推荐，绝不能形成 Router → Skill → Router 循环。

## 渐进式读取 references

只读取当前风险和产物真正需要的 reference：

- 仅在 `audit` 读取审计材料；
- 仅在数据库任务读取数据库材料；
- 仅在发布任务读取发布材料；
- 仅在迁移任务读取迁移材料；
- 只有出现对应决策或证据缺口时，才读取 Skill 专项检查清单。

Skill 启动时不得预读全部 references。
