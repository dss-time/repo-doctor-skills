# 架构摩擦详细检查表

只在确认候选资格或准备 audit 输出时读取。

## 证据问题

- 每个调用方除了声明接口外还必须知道什么？
- 哪些规则在调用方或 adapter 中重复？
- 一个领域行为变化会迫使哪些无关文件一起修改？
- 测试观察稳定行为，还是绑定内部协作顺序？
- 删除模块后，哪些复杂度消失，哪些转移到外部？
- 当前有哪些真实用例支持这项抽象？
- 哪些 ADR 限制接缝、兼容性或迁移？

## 方案比较

比较接口表面、被隐藏职责、调用方迁移、兼容性、运行时影响、测试接缝、运维发布、回滚成本和不确定性。存在有实质差异的保守方案时必须纳入。

## 拒绝条件

只由文件长度、命名偏好、目录深度、新奇程度、美化清理、没有变更压力的单一调用方或假想未来复用支持的问题，不得成为候选。
